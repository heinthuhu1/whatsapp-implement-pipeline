# Reproducibility package: synthetic worked example

This folder accompanies the methods paper describing a Python pipeline that turns a WhatsApp group-chat export into implementation metrics. It contains everything needed to run the pipeline end to end without access to the programme's data:

| File | Contents |
|---|---|
| `synthetic_whatsapp_export.txt` | A fully synthetic WhatsApp group export (361 messages and notices, 4 November 2024 to 28 February 2025, eight fictional senders, English, Roman Urdu and some Urdu script, 57 case-report messages in two template generations, voice-note and media placeholders, deleted-message and group notices). Every name, place, case and message is invented. |
| `synthetic_voice_notes.csv` | Synthetic output of the optional transcription stage (93 voice notes with invented Urdu transcripts and English translations), so that the hosted speech-to-text service is not needed. |
| `synthetic_settings.yaml` | The configuration used for the published demonstration (identical lexicons and thresholds), with study phases matching the synthetic date range. |
| `LEXICONS.md` | Every keyword lexicon in full, with term counts, language and the matching rule. |
| `PROCESSING_RULES.md` | Every parameter and processing rule, with the file and function that implements it. |
| `MODEL_VERSIONS.md` | Sentiment-model identifier and revision, speech-to-text model and endpoints, Python and package versions. |
| `synthetic_outputs/` | Created by the worked example below (not needed in advance). |

The synthetic export was generated by `revision/analyses/repro_00_make_synthetic.py` (fixed seed; re-running it produces the identical file). The pipeline code itself is in `src/` at the repository root and is not modified by anything in this folder.

## Requirements

* Python 3.12 and the packages in `requirements.txt` (exact versions used for the paper are listed in `MODEL_VERSIONS.md`).
* The sentiment model `distilbert-base-uncased-finetuned-sst-2-english` (about 270 MB), downloaded once from the Hugging Face Hub. Nothing else is downloaded, and no message content leaves the machine.
* No OpenAI key is needed: the transcription stage is skipped.

```bash
git clone <repository-url> && cd <repository>
python3.12 -m venv venv
venv/bin/pip install -r requirements.txt
# one-off model download (the only network access in this example)
venv/bin/python -c "from transformers import pipeline; pipeline('sentiment-analysis', model='distilbert-base-uncased-finetuned-sst-2-english', revision='714eb0fa89d2f80546fda750413ed43d93601a13')"
```

## Worked example

### Option 1: one command

```bash
venv/bin/python revision/analyses/repro_01_run_synthetic.py
```

This creates `revision/reproducibility/synthetic_outputs/` laid out as the pipeline expects, copies in the synthetic export, settings and voice-note table, and runs each stage of `src/` unchanged with that folder as the working directory (stage 02 is skipped). It writes `stage_status.csv`, `run_log.txt` and `run_summary.txt` alongside the outputs.

### Option 2: step by step

Every stage reads `config/settings.yaml` and resolves its paths relative to the current directory, so any empty folder can serve as a run directory:

```bash
REPO=$(pwd)
RUN=$REPO/revision/reproducibility/synthetic_outputs
mkdir -p $RUN/config $RUN/data/raw $RUN/data/processed
cp revision/reproducibility/synthetic_settings.yaml   $RUN/config/settings.yaml
cp revision/reproducibility/synthetic_whatsapp_export.txt $RUN/data/raw/whatsapp_export.txt
cp revision/reproducibility/synthetic_voice_notes.csv $RUN/data/processed/voice_notes.csv
cd $RUN
export HF_HUB_OFFLINE=1          # model already cached
for s in 00_anonymise 01_parse 03_engagement 04_network 05_sentiment 06_fidelity 07_triangulation 08_visualise 09_table1; do
  $REPO/venv/bin/python $REPO/src/$s.py
done
```

To use your own export instead, place it at `data/raw/whatsapp_export.txt` in a run directory, edit the phases and lexicons in `config/settings.yaml`, and run the same commands (or `bash run_pipeline.sh` from the repository root, which uses the repository's own `config/` and `data/`).

### What each stage produces on the synthetic data

All nine local stages completed without error on the synthetic export (Python 3.12.4, packages as in `MODEL_VERSIONS.md`):

| Stage | Status | Main outputs (in `synthetic_outputs/`) | Synthetic result |
|---|---|---|---|
| 00 anonymise | ran | `data/interim/anonymised_export.txt`, `config/sender_lookup.csv`, `data/interim/anonymisation_warnings.log` | 8 senders coded P001 to P008; numbers, one @-mention and in-body names redacted; one review flag (`Sparrow`) |
| 01 parse | ran | `data/interim/messages.csv`, `data/interim/case_reports.csv` | 361 rows (250 text, 93 voice notes, 8 images, 10 system notices); 57 case-report messages reduced to 53 records after de-duplication by case number |
| 02 voice notes | skipped | (hosted API) | replaced by `synthetic_voice_notes.csv` |
| 03 engagement | ran | `data/processed/engagement_metrics.csv` | weekly volume, 1 velocity-spike day, 5 silence periods over 48 h, after-hours rates, response latencies |
| 04 network | ran | `data/processed/network_edges.graphml`, `network_metrics.csv` | 8 nodes, 25 edges |
| 05 sentiment | ran | `data/processed/sentiment_metrics.csv` | daily, 7-day and 14-day sentiment; urgency, hedging and peer-support rates by phase |
| 06 fidelity | ran | `data/processed/fidelity_metrics.csv` | ToC coverage by phase, workaround flags, urgency-response latencies |
| 07 triangulation | ran | `data/processed/implementation_summary.csv` | one row per phase |
| 08 figures | ran | `data/processed/figures/fig1` to `fig5` | five figures |
| 09 Table 1 | ran | `data/processed/table1_overview.csv`, `.txt` | cross-domain Table 1 |

The numbers are properties of the invented data and carry no substantive meaning.

## Known behaviours reproduced by the example

The example deliberately runs the released code unchanged, so it reproduces two behaviours that users should be aware of (both are documented in `PROCESSING_RULES.md`):

1. **Voice-note translations are not joined to messages.** The anonymiser replaces the eight-digit date inside voice-note file names with `[NUMBER]` (rule A4), so the file name kept by the parser (`-WA0009.opus`) no longer matches the transcription table and stages 05 and 06 score the placeholder text instead of the translation. In the synthetic run, 0 of 93 voice notes are joined. A fix is described under rule A4.
2. **Some notices are parsed as text.** The end-to-end encryption notice and similar notices without a sender are typed `text` rather than `system` (rule B5 note) and are included in message counts.

## Existing unit tests

`venv/bin/python -m pytest tests` uses synthetic strings only. At commit `abca565`, 45 tests pass and 5 fail because the tests predate later changes to function signatures (`anonymise_text` now returns six values) and to the voice-note stage; the failures do not involve the stages' outputs.

## Data protection

This folder contains no programme data: no real names, messages, case details or places other than the programme sites already named in the paper. Do not copy anything from `data/` into this folder.
